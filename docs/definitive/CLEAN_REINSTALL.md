# Clean Reinstall

Direct owner requirement, October 11, 2026: Reinstall must leave one fresh installation after repeated versions were installed into the same owned folder, preserving disc images, saves and configurations. The publication owner assigned this ahead of incremental archive delivery. Baseline: `cb6168ba043991ad0b313111af02c4cba0f57f2d`.

Reinstall downloads every managed file and verifies the complete replacement before removing old application data. Repair keeps its selective behavior. The verified replacement inventory also supplies known application paths for old-folder census. Missing/corrupt old manifests use a bounded conservative census; retain uncertain owner contents inactive while removing recognized application/bootstrap/library/bundled archives. No historical application payload verification is required before Reinstall: damaged old packages and stray `config.conf` inside a release must not block preservation/replacement.

Before activation, record the original active private generation’s exact size/hash inventory, copy it, and compare both the source after copy and destination against that original inventory. A destination-only receipt is insufficient. Preserve distinct historical private generations/snapshots, legacy flat files and personal files found in old managed workspaces/releases under the new private generation’s `recovered-reinstall/<original relative path>`. Active choices remain authoritative; different historical files are never silently overwritten. Unknown owner files are retained in this inactive area. Existing `isos` stays untouched; loose images are preserved with their original location recorded in the recovery area. Custom mods remain protected; all seven bundled HD families, including renamed archives recognized by their bounded class-directory identity, are moved out of the loaded custom-mod directory into `recovered-reinstall/disabled-bundled-mods`.

Never follow personal symlinks. Recognized workspace links into this installation’s managed data/releases are disposable links; external or unrecognized personal links stop preservation before cleanup. Obsolete application links may be unlinked without traversing their targets. No other installation or external image is changed.

Activate the fully verified package, private generation and repaired bootstrap pair, keeping the accepted current-generation floor. Clear previous/retained/obsolete recovery pointers. A durable `.clean-reinstall.properties` journal binds the fresh release/data identities and preservation receipt checksum. Cleanup starts only when the active state matches that journal and the complete replacement and protected receipt verify. Refresh the last-good state before deleting obsolete references. Remove old releases, old data/snapshots/workspaces, extraction/release recovery copies and installer/source/application leftovers, including recognized legacy portable/contents/installer ZIPs and root HD bundles; create one fresh workspace. Keep ownership, current state/bootstrap pair, disc folder and live lock inodes. Preserve the running Java cache when located inside the owned root; `.java-path` is refreshed from the Java 25 process actually performing the verified operation.

Failure before activation leaves original personal data and the active state authoritative. Interruption after activation leaves the journal; next locked maintenance operation verifies preservation and resumes cleanup. Receipt corruption fails closed. Delete the journal only after cleanup and directory synchronization complete. A successful clean Reinstall has no old-version Restore option; ordinary Update/Restore behavior is unchanged.

Validation is headless with isolated owned roots and synthetic packages, discs and saves. Required cases include multiple versions, conflicting personal generations, flat/stray configurations, all seven duplicate mod families, renamed mod identity, exact preservation, cancellation, malformed replacement, bootstrap failure, game lease exclusion, interrupted cleanup and corrupted preservation receipt. This does not prove physical Steam Deck gameplay or actual interactive manager behavior.
