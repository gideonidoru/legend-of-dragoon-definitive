# Required submap preparation completion

Actual caller probes reproduced three defects after loader failures became visible: missing RetailSubmap assets still invoked the success callback, failed environment preparation left SMap waiting forever, and failed startup reads advanced into environment loading because the I/O counter reached zero. Worker callbacks also changed media stages directly and could commit into a replaced scene or engine state.

SMap now awaits the full required preparation chain for startup, environment and objects/overlays. Startup reads and parses NEWROOT plus all six savepoint/effect files before publishing their objects together. Success and failure are queued through the render owner; completion checks the current engine, phase, scene identity where relevant, and a generation that also invalidates when the state is destroyed. A superseded result cannot advance a newer load even if its scene and phase happen to match. The loader I/O counter no longer stands in for startup parsing completion.

Required failures retain their cause and identify startup, environment or assets. The render callback surfaces them through the engine's existing error shutdown instead of hanging or treating damaged assets as ready. This is explicit failure handling, not asset repair or a new return-to-title recovery interface. No saves or original assets are changed. Optional native environment image prewarming still retains its existing normal-preparation fallback.

Submap adds a future-returning `loadAssets()` contract. Its default bridges existing callback implementations and synchronous exceptions; legacy implementations must override the future method to report asynchronous failures that their callback API cannot express. RetailSubmap returns the complete object and optional overlay preparation chain with failures intact. Its existing `loadAssets(Runnable)` method remains available and invokes success only after successful preparation. A RetailSubmap-derived extension that customizes preparation should override the future method used by SMap; keeping the old method alone does not override that new entrypoint.

`SubmapLoadingReliabilityTest` uses bounded isolated JVMs, synthetic files, actual loader/parsers and SMap caller paths. The initial 12-case baseline fails 10 cases and retains two healthy controls. The expanded 19-case correction additionally covers script parsing and overlay failures, existing Submap callback bridging, synchronous preparation rejection, obsolete errors, destroyed-state completions, and superseded success in the same scene/phase. Completion and failure cases execute the complete production `onDraw` callback with an in-memory Noop window/backend; no native application window or audio output is created. Healthy callbacks, parsed startup publication and overlay error propagation are asserted, not inferred from an empty error log.

These checks do not qualify a full campaign, original or HD movie audio recovery, executor shutdown/queue policy, physical graphics-driver performance, or Steam Deck rendering/head binding. The correction is a narrow scene preparation increment following the loader foundation.
