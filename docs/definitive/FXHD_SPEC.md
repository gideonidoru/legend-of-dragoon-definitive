# Full FxHD coverage

The owner explicitly replaced the field-only milestone with full FX coverage. This specification supersedes the old batch restriction. Complete the entire retail texture-backed effect catalog and document every procedural, framebuffer, controller and other-owner route. Do not stop after a selected subset.

1. Census actual load roots and named field/world/title assets directly, including valid padded TIMs absent from the prior CSV. Bind every discovered texture source; deduplicate identical source pixel/palette content without conflating encoded source hashes. Record missing optional roots guarded by the engine and non-texture support files explicitly.
2. Generate all unique jobs with pinned local neural tools and a reproducible shared recipe. Publish custom outputs and source/output/tool hashes. Keep discs, original extracted files, inference inputs/logs/comparison images, binaries and weights outside Git and installation.
3. Preserve live original palette animation, source visibility and STP, visible black, blend modes, original geometry/UVs, simulation timing and particle counts. Palette-live indexed detail must follow native VRAM copies, masked writes, overlapping traversal, CPU row rotations and world-menu backup/restore. Do not freeze whole animated families to one RGB palette.
4. Apply through standard, TMD and battle-TMD draws. Protect UIHD queues and earlier explicit HD replacements. Native writes invalidate only overwritten detail; obsolete source callbacks cannot resurrect overwritten owners. Missing/corrupt/mismatched resources retain original rendering. Mod disable/re-enable and graphics reinitialization must be safe.
5. Retain shared bounded image caching, SMAA, emission/bloom, save-point lighting, scene/material lighting and reduced-flashing behavior. No inference or per-particle decode/upload in game. Smoke/dust/footprints keep original unlit behavior. Account fixed GPU/CPU/staging/snapshot budgets separately; no mip or linear filtering of palette controls.
6. Provide a public full source ledger and consumer-route ledger with no unclassified consumers. Distinguish source bindings, unique outputs, changed outputs and rendering acceptance. Procedural effects use current-resolution geometry and framebuffer effects sample the live rendered image; UI/body/environment artwork retain their corresponding mods.
7. Build FxHD-v1.0.0.jar through the normal seven-module installer. Preserve saved mod choices, manual old copies, attribution and current-only combined release policy. Verify all declared runtime output hashes and default package inclusion, including incremental builds with stale JARs.
8. Run synthetic production/import rollback tests, native CPU VRAM ownership/animation tests, a complete private-source index/hash probe, actual shipping shader fixtures in hosted isolated software OpenGL, and full headless build/package regressions. Source and synthetic verification do not establish every scene's appearance or physical Steam Deck performance; those acceptance flags remain false until observed.
9. Have independent standards/spec reviews, resolve findings, and merge the complete implementation into main. The orchestrator owns combined publication; no separate FxHD release.
