# QoL, controls and campaign acceptance

This matrix distinguishes implemented behavior, source/CPU evidence, and pending played
acceptance. Passing headless tests does not establish complete campaign or physical Deck
acceptance. Both presets retain normal progression; switching presets cannot undo rewards
already earned. Guidance/journal remains planned and must not be described as shipped.

| Domain | Source contract and automated evidence | Remaining acceptance |
| --- | --- | --- |
| Faithful / Definitive | `PresetDefinition` supplies all 32 explicit campaign/save choices; `DefinitivePresets` rejects global entries and wrong types. `PresetDefinitionTest` checks shared mechanics and deliberate differences. | Create both presets, switch an existing campaign explicitly, save/reload, verify global device/artwork settings and prior XP/gold remain intact. |
| Equipment / bag | `EquipmentSort`, Equipment/ItemList screens provide Slot/Name/Power, temporary type filters and binding-aware hints. `EquipmentSortTest` covers comparator/filter behavior. | Controller-only equip/unequip/filter/sort/use/back across empty, full and overflow inventories, all equipment types; no item or quantity loss on cancel. |
| Shop quantity | `QuantityScreen`, `ShopQuantity`, ordinary item/equipment extensions and `ShopScreen.sellQuantity` delay transfers until Confirm; hook denial stops a batch and only completed units are charged. `ShopQuantityTest` and `InventoryContractsTest` cover cancellation at the transfer seam, capacity, grouping/protection, affordability and purchase-hook data. | Exercise the actual modal Confirm/Back/mouse paths, changed sale prices, single equipment equip prompt, partial batch, protected/mod-data items, 99-unit limit and full inventory. Helper cancellation tests alone do not verify UI event routing. |
| Rewards / save compatibility | Battle snapshots validated independent XP/gold multipliers at initialization, applies them after reward listeners and saturates totals. `RewardScalingTest` covers rounding/invalid inputs/bounds; `InventoryContractsTest` covers campaign config save/reload and isolation. New IDs do not reinterpret old Battle Rewards settings. | Multi-enemy, summoned enemies, drops/scripted rewards, reserve/dead-party distribution, XP/level/mastery persistence, save/restart and old campaign loading across all four discs. External reward mods compound final scaling; each supported overhaul needs a named compatibility run. |
| Addition feedback | `AdditionFeedback` and Battle hooks report resolved manual outcomes with bounded expiry, no damage/mastery/window changes. `AdditionFeedbackTest` covers outcomes and lifetime. | Played manual/automatic/counter/timeout Additions and readability on Deck at native scale; preserve earned mastery and timing settings across reload. |
| Remaps / hints | `KeybindsScreen` snapshots opening bindings, preserves detached editor globals, commits accepted changes; `MenuScreen` draws hints from current bindings and input family. | Confirm/cancel remapping, timeout, removing all bindings, conflicting bindings, keyboard/gamepad family switch and reload. No complete screen-level remap acceptance is claimed by existing CPU input tests. |
| Hotplug / input edges | `SdlPlatformManager` device-aware disconnect recovery and `ControllerDisconnectTest` cover cancellation, callback ordering and surviving sources. `SimulationRendererTest` covers focus/tick edge consumption. | Physical unplug/reconnect, multiple devices, disconnect during quantity/Addition input, suspend/resume and remapped controllers. Synthetic bookkeeping is not proof of SDL delivery. |
| Steam Input | Existing IGNORE_WHEN_GAMEPAD_USED workaround suppresses keyboard events while native gamepad buttons/axes are held. Disconnect recovery clears the removed device's suppression ownership. | Separate native-gamepad and keyboard-emulation layouts, duplicate-event ordering, action glyph consistency and simultaneous real keyboard input. Virtual keyboard source identification remains unavailable in this workaround. |
| Readability / accessibility | Binding-aware hints, optional feedback, remapping and existing text/timing options are implemented. | Screen-level focus/escape paths, contrast, small-screen text, non-colour cues, long/localized labels and all setting controls. No screen reader, complete accessibility or physical-device certification is claimed. |
| Journey guidance / journal | Optional journal/hints remain D13 in BACKLOG; no gameplay journal/progression consumer implementation was found in this source snapshot. Installer transaction journals are unrelated. | Establish source-proved progression events, spoiler policy, immutable story flags and save/reload contract before implementation. No acceptance credit for a planned feature. |

The material census and controller recovery are separate changes. The field/overlay CPU
checkpoint does not prove battle GPU residency or the cause of the reported scaling flicker.
