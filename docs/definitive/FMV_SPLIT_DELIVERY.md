# FMVHD code and data delivery

Spec: retain the approved 18 enhanced films as byte-identical individually checksum-managed `gfx/fmvhd/videos/<sha256>.mp4` files, with a small FMVHD code mod and canonical manifest. Preserve all seven mod IDs/switches, source identity, attribution, existing workspace artwork links and all playback/clock/decoder behavior. No old-client bridge and no independent publication; this is for the next coordinated release after frozen fb94.

The manager imports matching enhanced films from its hash-pinned installed legacy FMVHD JAR into staging only. It validates both archived metadata/source identity and complete extracted bytes; unsafe, duplicate, missing, corrupt, truncated and mismatched inputs are rejected. Failed import may use a verified network object; partial candidates cannot activate. Full reinstall intentionally downloads fresh files. Subsequent code-only updates reuse all movies; a one-film change downloads only that film.

Approved test seams are the installed-file lookup used by the mod, strict canonical manifest/package closure, actual FileDelivery/InstallStore update transactions with request-counting transport, legacy streaming import with source/archive closure, and headless resource opening/decoding. Required proof includes all 18 real payload hashes, normal managed gfx links, forbidden nested links/paths, switch/source/first-owner gates, request counts for initial split/code-only/one-film/repair/reinstall, cancellation and stream/resource cleanup. Synthetic tests do not establish physical Deck/GLES/campaign acceptance.

Source builds fetch the same 18 checksum-pinned `file-<sha>` movie objects used by runtime delivery, with committed manifest/provenance/notices. The historical aggregate ZIP digest only pins an optional local import/bootstrap input; no aggregate ZIP is emitted or required for next-format publication. Original IKI movies, disc images, extracted private inputs, decoded masters and production caches are excluded from public deliverables. Notices and provenance remain distinct from the code license. The coordinated publication owner controls asset reuse, exact-source gates, carrier promotion and pruning.

The approved DEMO2 and DRAGON2 payloads are identical. All 18 named records and their distinct native-source gates remain required; the physical inventory contains 17 immutable movie objects. Shared digests must have consistent sizes.

## Integration ownership

This branch supplies the canonical film contract, runtime lookup, optional legacy import, per-film build staging and pure semantic package verifier. The manager owner integrates `FmvPackageAssets.verify(root, hashes)` after generic package hash verification and validates current-revision movie descriptors against inventory paths/hash/sizes before fetching. The generic chunk/range assembly and further FileDelivery/PackageManifest edits belong to that owner. The publication owner seeds/reuses the individual carrier objects, updates source/CI input closure, and promotes the next complete candidate. The old aggregate-source publication tests are the publication owner's migration work; changing their expectations here would conflict with the frozen current download.

## Validation commands

- `python3 scripts/test-fmvhd-staging.py` exercises individual carriers, unchanged/one-film requests, shared objects, bounded transfer failures, attribution/source pins, unknown output preservation and rollback.
- `./gradlew deliveryTest` includes synthetic manifest/package/import/update controls and existing profile/playback regressions. With staged assets, both actual-movie pacing tests run over all 18 names at 30/60/120 Hz.
- `./gradlew fmvSplitSourceProbe -PfmvLegacyRelease=<verified-private-installed-release>` requires the actual staged media and small mod JAR. It loads that JAR, accepts the normal top-level artwork link, checks earlier ownership/native-source mismatch, fully decodes all 31,184 enhanced frames, verifies every cadence/tail and worker shutdown, and imports the real hash-pinned legacy payload into disposable staging with zero movie network requests. Optional `-PfmvHdAssets=<approved-local-bootstrap>` avoids fetching source objects before the coordinated carrier cutover.

The probe validates the preserved enhanced frame counts, not equality to the 31,177 native frames; existing extraction warnings account for the recorded difference. It drains PCM without retaining it. Actual prefix pacing uses the native loopback mixer; full-duration source decoding is not a real-time wall-clock playback test. Physical Steam Deck/GLES, battle transitions and campaign acceptance remain separate.
