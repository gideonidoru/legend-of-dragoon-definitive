# Dragoon Modifier — optional overhaul assessment

Inspected 2026-10-09 against official baseline `fba1543543865e29ee572f479003d9b47158eeb3` (Java 25). Recommendation: evaluate the author's standalone mod as an explicitly optional, separate-campaign difficulty overhaul. Keep it outside faithful mode. Do not copy its source, presets, graphics or scripts into Definitive, or redistribute its package, until their applicable terms are established.

## Modularity and API compatibility

[Build configuration](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/build.gradle.kts) targets Java 25, version `2.2-SNAPSHOT`, depends on unpinned `legend:lod:snapshot` with `mavenLocal()` enabled, and declares mod-loader 4.3.3. Our [baseline build](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/build.gradle) uses mod-loader 4.3.4. Matching language level and `@Mod(version="^3.0.0")` are compatibility declarations, not proof of exact engine compatibility or reproducible package provenance.

The [entry point](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/DragoonModifier.java#L215) registers events, character templates, equipment, items, Additions, spells, actions and stats under `dragoon_modifier`. It does not require replacing engine Java files. However, a 3,194-line main class touches global battle/submap state and uses highest/lowest-priority event handlers, so it is broadly coupled rather than a small balance-data adapter. It reads external preset CSVs and textures/scripts through paths relative to the working directory; the mod JAR alone is insufficient.

Source-only check: **all 46 Java files compiled successfully** using local Corretto 25 (`javac --release 25`) against `build/libs/lod-game-snapshot.jar` and its dependency JARs. Those engine APIs are based on the fixed official baseline with existing Definitive build/updater changes; inspected character/save/event source paths have no project diff from baseline. Compiler notes report deprecated APIs and unchecked operations. Source/classes/output remain in `/private/tmp/dragoon-modifier-research`; no release JAR or game was executed. This validates referenced signatures against the locally built API, not mod-loader discovery, published binary ABI, CSV/script coherence or gameplay.

## Persistence and source risks

1. **Removal is not proven safe.** The baseline [V10 serializer](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/src/main/java/legend/game/saves/serializers/V10Serializer.java#L136) writes character `templateId` and resolves it through the installed registry when reading. It also persists equipment/item registry IDs. Modifier campaigns therefore carry `dragoon_modifier` dependencies; disabling the mod cannot be assumed to restore stock characters/inventory or open those saves. Difficulty/settings live in [campaign_config.dcnf](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/src/main/java/legend/game/saves/Campaign.java#L40); CSV contents/hashes are not serialized by this mod. Changing external CSVs can change later behavior of an existing campaign. Keep campaign, config and exact pack/version together and define explicit migration rules.
2. **Difficulty changes are partial until restart.** [Difficulty change handling](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/DragoonModifier.java#L496) reloads only monster stats/rewards and reapplies locks; registries/templates/shop/spell/item data are not rebuilt there. The [selector](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/configs/DifficultyEntryConfig.java) restricts active-campaign choices mainly to the current preset and switching between the two hard variants. It assumes the preset folder exists and uses filesystem enumeration indices when selecting dropdown entries. No supported cross-preset save conversion was established.
3. **Verified stat multiplier defect.** [Monster handler lines 3011–3024](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/DragoonModifier.java#L3011): AT, MAT, DF and MDF each check their own setting but all multiply by `MULTI_SPD`. For example, AT=200 with SPD=100 leaves attack unchanged; AT=101 with SPD=200 doubles it. HP and SPD use their own settings correctly. Correct and behavior-test independently varied values before presenting these controls as reliable.
4. **Faithful-mode leak in warp handler.** [inputPressed](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/DragoonModifier.java#L1145) warps between Moon/Ulara cuts 729 and 526/527 on the Coolon action without the hard-mode/story checks used by its notification handler. Source suggests the warp can apply in Retail mode; actual input delivery remains unverified.
5. **Data and output failure paths.** CSV parsing uses fixed columns/direct enemy-index rows and throws for missing/malformed files; there is no preset-schema validator or graceful original-data fallback. Damage-report writing throws if its output path cannot be opened. Test incomplete packs, read-only install paths, corrupt rows and unknown registry IDs. [CSV loading](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/DragoonModifier.java#L380), [monster indexing](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/DragoonModifier.java#L2982).

## Existing upstream overlap and next slice

**Battle Rewards pairing needs an explicit combination contract.** The modifier's [EnemyRewardsEvent handler](https://github.com/Legend-of-Dragoon-Modding/sc-dragoon-modifier/blob/ea1c2d95e1c87a92bb1389431567d30bd275ea2b/src/main/java/lod/dragoonmodifier/DragoonModifier.java#L3040) runs at `Priority.LOWEST`, calls `event.clear()` unconditionally and replaces XP, gold and drops from its preset, even in Retail NA. It can erase changes made by an earlier rewards listener. Our [baseline reward event](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/src/main/java/legend/game/modding/events/battle/EnemyRewardsEvent.java) exposes shared mutable XP/gold/drop fields. Pair interaction and listener ordering with Battle Rewards have not been executed or proved here; do not promise stacking. Specify which preset supplies base rewards and which adjustment happens afterward, preserving protected/new modifier drops, before enabling both.

Our baseline already has [UnlockPartyConfig](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/src/main/java/legend/game/modding/coremod/config/UnlockPartyConfig.java), [ExtendedDragoonActionsConfig](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/src/main/java/legend/lodmod/config/ExtendedDragoonActionsConfig.java), [TransformAction with detransformation choices](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/src/main/java/legend/lodmod/battleactions/TransformAction.java), configurable inventory/stack sizes and [CharacterTemplate](https://github.com/Legend-of-Dragoon-Modding/Severed-Chains/blob/fba1543543865e29ee572f479003d9b47158eeb3/src/main/java/legend/game/characters/CharacterTemplate.java) progression seams. Do not duplicate these engine facilities to reproduce overlapping toggles. MonsterStatsEvent, EnemyRewardsEvent, RenderEvent and BattleEndedEvent provide existing seams for separately specified balance, HP or diagnostics work. HP disclosure and party/progression shortcuts should themselves be opt-in under the project's faithful-mode contract.

Recommended next implementation candidate: an external-mod compatibility/provenance entry and isolated optional campaign profile, after terms and runtime prerequisites are resolved. Before recommending it to players, verify package hash/content/provenance, load on the exact engine SHA, independently vary each multiplier, exercise both hard presets and story caps, save/restart/load with exact CSV versions, test missing-mod recovery without overwriting the original save, and assess controller navigation/HP readability on Steam Deck. Any extracted HP/diagnostic implementation needs its own narrowly defined behavior and established reuse terms; this research does not authorize copying.
